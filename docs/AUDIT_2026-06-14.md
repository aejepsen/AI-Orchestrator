## Findings

### SEGURANCA

```
[MEDIO → RESOLVIDO] Exception detail leak via SSE
Onde: gateway/main.py worker() — emit("error", {"detail": str(exc)})
Problema: str(exc) de LLMError, httpx.TransportError ou erros internos pode vazar paths do filesystem, URLs internas, stack traces parciais para o cliente via SSE.
Impacto: Information disclosure (STRIDE-I). Atacante mapeia infraestrutura interna.
Fix: Substituir str(exc) por mensagem generica no SSE; logar exc completo server-side (ja faz via logger.exception).
Resolucao: SSE error handler sanitizado — mensagem generica pro cliente ("Erro interno. Tente novamente."), traceback completo server-side no log.
```

```
[MEDIO → RESOLVIDO] Langfuse com credenciais default inseguras
Onde: .env.example, docker-compose.yml — pk-lf-local, sk-lf-local, mysecret-change-in-production
Problema: Defaults para LANGFUSE_PUBLIC_KEY, LANGFUSE_SECRET_KEY, NEXTAUTH_SECRET e SALT sao valores fixos documentados. Se deploy for feito sem alterar, Langfuse fica aberto.
Impacto: Acesso nao autorizado a traces LLM completos (prompts, respostas, tool calls).
Fix: Remover defaults do compose; usar variavel required (${VAR:?msg}) como ja faz com INTERNAL_API_KEY.
Resolucao: LANGFUSE_NEXTAUTH_SECRET e LANGFUSE_SALT agora required (${VAR:?msg}) — compose e fail-closed sem defaults inseguros.
```

```
[MEDIO → RESOLVIDO] Qdrant sem autenticacao
Onde: docker-compose.yml — qdrant service, porta 127.0.0.1:6333
Problema: Qdrant roda sem API key. Qualquer processo na maquina host pode ler/escrever no banco vetorial.
Impacto: Tampering no indice de roteamento (envenenar routing_examples para redirecionar queries). Mitigado por bind 127.0.0.1.
Fix: Habilitar QDRANT__SERVICE__API_KEY no container e propagar ao gateway.
Resolucao: QDRANT__SERVICE__API_KEY habilitado no container e propagado ao gateway via header api-key.
```

```
[MEDIO → RESOLVIDO] RateLimiter in-memory sem eviction — memory leak
Onde: gateway/security.py — self._hits dict de deques
Problema: Cada IP unico cria uma entrada no dict que nunca e removida (deque so limpa timestamps expirados, mas a key persiste). Sob ataque distribuido (botnets, IPs rotativos), dict cresce indefinidamente.
Impacto: OOM do container gateway apos exposicao prolongada. Em PoC single-node e aceitavel; em producao e DoS.
Fix: Adicionar TTL-based eviction periodico (ex: a cada 1000 requests, remover keys com deque vazio) ou migrar para Redis.
Resolucao: max_entries=10000 + eviction periodico de entries expiradas implementado no RateLimiter.
```

```
[BAIXO] Ollama/Qdrant com :latest tag
Onde: docker-compose.yml — image: ollama/ollama:latest, qdrant/qdrant:latest
Problema: Tags :latest sao mutaveis; rebuild pode trazer breaking changes sem aviso.
Impacto: Supply chain — build nao-reproduzivel. Aceitavel em PoC; inaceitavel em producao.
Fix: Pinar por digest ou tag de versao especifica.
```

```
[BAIXO] Services Dockerfile nao pina versoes
Onde: services/Dockerfile — pip install "fastapi>=0.115,<1" "uvicorn>=0.34,<1"
Problema: Range de versao permite minor/patch updates automaticos no build. Gateway pina exato (bom), services nao.
Impacto: Build nao-reproduzivel; potencial incompatibilidade silenciosa.
Fix: Usar requirements.txt com versoes exatas (services/requirements.txt ja existe mas nao e referenciado no Dockerfile).
```

```
[BAIXO] ALLOW_OPEN_ACCESS como bypass de auth
Onde: gateway/security.py AccessTokenGuard.allows()
Problema: ALLOW_OPEN_ACCESS=1 sem ACCESS_TOKEN desabilita toda autenticacao. Documentado como dev-only, mas sem protecao contra uso acidental em producao.
Impacto: Bypass total de auth se variavel vazar para ambiente de producao.
Fix: Log WARNING mais agressivo; considerar checar presenca de TUNNEL_TOKEN ou hostname para recusar ALLOW_OPEN_ACCESS em contexto de producao.
```

### ARQUITETURA & AGENT LOOP

```
[MEDIO] HITL desabilitado — todo write passa sem confirmacao
Onde: gateway/main.py worker() — on_confirm comentado; graph.py confirm_dispatch auto-aprova
Problema: Todas as operacoes destrutivas (DELETE, PUT) sao executadas sem confirmacao humana. O mecanismo existe (interrupt(), /resume endpoint, ConfirmCard.tsx) mas esta desabilitado.
Impacto: Agente LLM pode executar delecoes/updates nao-intencionados baseado em interpretacao errada da query. Mitigado pelas regras de negocio nos servicos (ex: nao deleta seller com pedidos).
Fix: Implementar deteccao de write vs read intent para habilitar HITL seletivamente. Ja documentado como backlog.
```

```
[BAIXO] MemorySaver in-memory como fallback de checkpointer
Onde: gateway/graph.py — fallback para MemorySaver se SqliteSaver indisponivel
Problema: MemorySaver perde todo estado conversacional no restart do container. THREAD_DB_PATH=/tmp/threads.db no compose aponta para tmpfs dentro do container (nao persistido em volume).
Impacto: Historico de conversa perdido no restart. Aceitavel em PoC.
Fix: Montar volume para o path do threads.db ou usar path em /data.
```

### PERFORMANCE & CUSTO

```
[BAIXO] Fan-out serializado pelo Ollama single-instance
Onde: gateway/graph.py dispatch — ThreadPoolExecutor fan-out, mas Ollama serializa
Problema: Documentado e consciente. Fan-out de 3 dominios = 3x latencia sequencial do LLM. LLM_TIMEOUT_S=900 (15min) compensa mas e lento.
Impacto: UX degradada em queries multi-dominio (minutos de espera). Aceitavel para PoC em RTX 3060.
Fix: Escala horizontal de Ollama (multiplas GPUs) ou batching nativo quando Ollama suportar.
```

### DADOS & CONCORRENCIA

```
[MEDIO → RESOLVIDO] SQLite sem WAL nem busy_timeout nos servicos
Onde: services/financas/db.py, services/estoque/db.py, services/vendas/db.py, services/rh/db.py
Problema: Nenhum servico configura PRAGMA journal_mode=WAL ou PRAGMA busy_timeout. Apenas foreign_keys=ON (estoque, rh, vendas). Financas nem isso.
Impacto: Fan-out do gateway pode disparar writes concorrentes no mesmo servico (ex: 2 requests simultaneos criando contas). Sem WAL, readers bloqueiam writers e vice-versa. Sem busy_timeout, "database is locked" imediato em vez de retry.
Fix: Adicionar PRAGMA journal_mode=WAL e PRAGMA busy_timeout=5000 em todos os db.connect().
Resolucao: PRAGMA journal_mode=WAL + PRAGMA busy_timeout=5000 adicionados em todos os 4 microsservicos.
```

### QUALIDADE & TESTES

```
[BAIXO] Cobertura de testes nao medida formalmente
Onde: gateway/tests/, services/*/tests/
Problema: Test suites robustos existem (sanitize, security, router, graph, agents, registry, circuit breaker, embedder, semantic_router, injection_detector, evals end-to-end), mas nao ha configuracao de coverage (pytest-cov) nem CI.
Impacto: Regressoes silenciosas possiveis. Test coverage parece alta por inspecao, mas nao verificada.
Fix: Adicionar pytest-cov + threshold minimo. Opcional para PoC.
```

```
[BAIXO] Evals dependem de estado do seed — nao isolados
Onde: evals/eval_domains.py, evals/eval_routing.py — rodam contra servicos live
Problema: Documentado como known issue. Evals acumulam estado entre runs (conta ja liquidada persiste). Precisa de reset de DB entre execucoes.
Impacto: Falsos negativos em re-execucoes de eval.
Fix: Script de reset de estado antes de cada eval run, ou teardown por caso.
```

### OBSERVABILIDADE

```
[BAIXO] Logs estruturados parciais
Onde: gateway/ — mix de logger.info com strings e json.dumps
Problema: Alguns logs sao JSON estruturado (circuit breaker transitions), outros sao strings formatadas. Inconsistencia dificulta parsing automatizado.
Impacto: Menor — monitoramento manual funciona; agregacao automatica prejudicada.
Fix: Padronizar todos os logs como JSON estruturado.
```

## Pontos Fortes (nao inflados como findings)

- **Seguranca em profundidade**: 4 camadas anti-injection (sanitize ChatML/tags, strip_injection regex, BERT classifier, routing guards deterministicos)
- **Least-privilege por design**: tools escopadas por dominio, system prompt isolado por agente
- **Anti-fabricacao solida**: system prompt exige fundamentacao em tool returns; agente nao inventa dados
- **Circuit breaker por dominio**: isola falhas de transporte sem derrubar outros dominios
- **Regras de negocio na API, nunca no LLM**: 422 com envelope acionavel reinjetado como observacao
- **Dockerfile multi-stage, non-root**: gateway e services rodam como user `app`
- **Bind 127.0.0.1 em todas as portas**: nenhum servico exposto diretamente
- **Constant-time token comparison**: hmac.compare_digest em ambos os boundaries
- **Healthchecks reais**: todos os containers com healthcheck funcional
- **Semantic router com consensus check**: rejeita vizinhos divergentes, threshold alto (0.92)
- **Degradacao graceful**: Langfuse fora nao impacta requests; injection detector fora cai em regex
- **Evals end-to-end**: routing + domains + injection com golden sets
